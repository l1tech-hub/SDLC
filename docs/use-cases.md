# Модель вариантов использования CafeCalc

Версия 0.1 · 17.11.2026 · Пастухов М. В., гр. 450501

Исходные данные: SDD, представление 001-context (UC-1…UC-8). Для устранения дублирования добавлены вспомогательные прецеденты UC-9…UC-11. Термины — в [glossary.md](glossary.md), правила BR-* и нефункциональные требования — в [supplementary-spec.md](supplementary-spec.md).

## 1. Диаграмма

![Диаграмма вариантов использования](uml/img/001-usecase-model.svg)

Исходник: [001-usecase-model.puml](uml/001-usecase-model.puml).

Принятые решения:

- Единственный актёр, внешних систем нет (SRS 2.4, REQ-SEC-002). Диалоги выбора файла — часть ОС, отдельным актёром не являются.
- Связь «актёр → прецедент» показана сплошной стрелкой от актёра: все основные прецеденты инициирует сотрудник.
- Основные прецеденты между собой не связаны (порядок их выполнения диаграмма не задаёт).
- `<<include>>` — UC-9 обязателен для UC-2, UC-3, UC-5. `<<extend>>` — UC-10 вызывается, только если сотрудник выбрал изображение; UC-11 — только при нехватке продуктов.

## 2. Актёр

| Актёр | Описание |
|-------|----------|
| Сотрудник кафе | Повар, кладовщик или администратор. Единственный пользователь: ведёт склад и меню, выполняет списание, смотрит журнал и создаёт резервные копии. Различий в правах нет. |

## 4. Описания прецедентов

### UC-1. Просмотреть склад, найти и выбрать продукт

**Описание.** Сотрудник видит список продуктов с остатками, фильтрует его по названию и выбирает продукт для дальнейших действий.
**Актёр.** Сотрудник кафе.
**Предусловия.** Приложение запущено; открыта вкладка «Склад».

**Основной поток.**
1. Сотрудник открывает вкладку «Склад».
2. Система показывает продукты, отсортированные по названию: название, остаток в граммах, миниатюра. Остаток меньше 300 г выделен красным (BR-13). Кнопки «Пополнить», «Изменить», «Удалить» недоступны.
3. Сотрудник вводит текст в поле поиска.
4. Система по мере ввода оставляет продукты, название которых содержит введённый текст без учёта регистра, и показывает «Найдено: N из M».
5. Сотрудник выбирает продукт в списке.
6. Система показывает сведения о продукте и включает кнопки «Пополнить», «Изменить», «Удалить».

**Альтернативные потоки.**
- 3a. Поле поиска пусто: показан весь список.
- 4a. Совпадений нет: список пуст, «Найдено: 0 из M».
- 2a. Файл изображения отсутствует или повреждён: вместо него показана заглушка; остальные данные отображаются.

**Постусловия.** Данные не изменены. Если продукт выбран, кнопки действий доступны.

### UC-2. Добавить продукт

**Описание.** Сотрудник вносит на склад новый продукт с названием, начальным остатком и необязательным изображением.
**Актёр.** Сотрудник кафе.
**Предусловия.** Открыта вкладка «Склад».
**Диаграммы.** [Деятельность](uml/003-activity-add-product.puml), [последовательность](uml/005-sequence-add-product.puml).

**Основной поток.**
1. Сотрудник нажимает «Добавить продукт».
2. Система открывает модальное окно «Новый продукт».
3. Сотрудник вводит название и остаток в граммах, при желании выбирает изображение, нажимает «Сохранить».
4. Система выполняет UC-9 для названия и остатка.
5. Если изображение выбрано, система выполняет UC-10.
6. Система начинает транзакцию, проверяет уникальность ключа названия и добавляет продукт.
7. Система фиксирует транзакцию, закрывает окно и показывает продукт в списке.

**Альтернативные потоки.**
- 3a. Сотрудник нажимает «Отмена» или `Esc`: окно закрыто, данные и файлы не изменены.
- 4a. Данные некорректны: ошибки показаны красным рядом с полями, окно открыто, шаг 3.
- 5a. Изображение не прошло проверку: сообщение об ошибке на русском, файл не копируется, шаг 3.
- 6a. Ключ названия уже занят или произошёл сбой записи: транзакция откатывается, скопированный файл изображения удаляется, показано сообщение; окно остаётся открытым.

**Постусловия.** Успех: продукт сохранён в БД вместе с ключом названия, изображение лежит в `images/`, продукт виден в списке. Отмена или ошибка: БД и файлы без изменений.

### UC-3. Пополнить, изменить, удалить продукт

**Описание.** Сотрудник увеличивает остаток выбранного продукта, правит его данные или удаляет продукт.
**Актёр.** Сотрудник кафе.
**Предусловия.** Открыта вкладка «Склад»; продукт выбран (UC-1).

**Основной поток («Пополнить»).**
1. Сотрудник нажимает «Пополнить».
2. Система открывает модальное окно ввода граммов.
3. Сотрудник вводит число граммов и подтверждает (`Enter`).
4. Система выполняет UC-9: только цифры, не менее 1, результирующий остаток не больше 10 000 000 г (BR-2, BR-3).
5. Система увеличивает остаток, сохраняет, закрывает окно и обновляет список.

**Альтернативные потоки.**
- A. «Изменить». Система открывает окно «Изменить продукт» с текущими значениями; сотрудник правит название, остаток, изображение; система выполняет UC-9, при выбранном изображении — UC-10, затем сохраняет в одной транзакции (уникальность ключа учитывается, продукт сравнивается с остальными).
- B. «Удалить». Система проверяет, входит ли продукт в состав блюд. Если нет, запрашивает подтверждение и после согласия удаляет продукт и его изображение. Если входит, удаление блокируется и показывается перечень блюд (BR-8).
- 4a. Ошибка ввода: сообщение рядом с полем, остаток не изменён, окно открыто.
- 3a. «Отмена» или `Esc`: окно закрыто, данные не изменены.

**Постусловия.** Успех: изменения сохранены, список и сведения обновлены. Отмена, ошибка, блокировка удаления: данные не изменены.

### UC-4. Просмотреть меню, найти блюдо, открыть карточку и рецепт

**Описание.** Сотрудник просматривает список блюд, ищет блюдо по названию и открывает карточку с составом и рецептом.
**Актёр.** Сотрудник кафе.
**Предусловия.** Приложение запущено; открыта вкладка «Меню блюд».

**Основной поток.**
1. Сотрудник открывает вкладку «Меню блюд».
2. Система показывает блюда, отсортированные по названию, с миниатюрами.
3. Сотрудник вводит текст в поле поиска.
4. Система фильтрует блюда по вхождению без учёта регистра и показывает «Найдено: N из M».
5. Сотрудник выбирает блюдо.
6. Система показывает карточку: изображение, название, состав (продукт и граммы на порцию), текстовый рецепт с сохранёнными переносами строк.

**Альтернативные потоки.**
- 4a. Совпадений нет: список пуст.
- 6a. Изображение отсутствует или повреждено: показана заглушка.

**Постусловия.** Данные не изменены; выбранное блюдо доступно для UC-5 и UC-6.

### UC-5. Создать, изменить, удалить блюдо

**Описание.** Сотрудник ведёт меню: создаёт блюдо с составом и рецептом, правит или удаляет его.
**Актёр.** Сотрудник кафе.
**Предусловия.** Открыта вкладка «Меню блюд»; для создания состава на складе есть продукты.

**Основной поток («Создать»).**
1. Сотрудник нажимает «Новое блюдо».
2. Система открывает модальное окно «Новое блюдо».
3. Сотрудник вводит название и рецепт, при желании выбирает изображение, добавляет в состав продукты и граммы на порцию, нажимает «Сохранить».
4. Система выполняет UC-9 (название, рецепт, состав: не менее одного продукта, без повторов, граммы по BR-6).
5. Если изображение выбрано, система выполняет UC-10.
6. Система в одной транзакции проверяет уникальность ключа названия и сохраняет блюдо вместе с составом.
7. Система закрывает окно и показывает блюдо в списке.

**Альтернативные потоки.**
- A. «Изменить»: окно «Изменить блюдо» с текущими данными; шаги 3–7 с обновлением.
- B. «Удалить»: после подтверждения система удаляет блюдо и его состав; записи журнала списаний сохраняются (снимки, BR-11).
- 3a. «Отмена» или `Esc`: ничего не сохраняется.
- 4a. Ошибки данных: сообщения рядом с полями, окно открыто.
- 6a. Ключ занят или сбой записи: откат, удаление скопированного файла, сообщение.

**Постусловия.** Успех: блюдо и состав сохранены атомарно. Отмена или ошибка: данные не изменены.

### UC-6. Списать продукты по блюду

**Описание.** Сотрудник одной кнопкой списывает продукты, необходимые для заданного числа порций блюда, с контролем остатков и записью в журнал.
**Актёр.** Сотрудник кафе.
**Предусловия.** Открыта вкладка «Меню блюд»; блюдо выбрано (UC-4).
**Диаграммы.** [Деятельность](uml/002-activity-writeoff.puml), [последовательность](uml/004-sequence-writeoff.puml), [состояния](uml/006-state-writeoff-panel.puml).

**Основной поток.**
1. Сотрудник вводит число порций.
2. Система проверяет, что число порций от 1 до 999, рассчитывает расход «граммы на порцию × порции» (BR-10) и показывает расход по каждому продукту; кнопка «Списать» становится доступной.
3. Сотрудник нажимает «Списать».
4. Система блокирует элементы управления, начинает транзакцию и перечитывает состав блюда и текущие остатки.
5. Система проверяет, что остатков хватает по каждому продукту.
6. Система уменьшает остатки и добавляет запись в журнал: время (UTC), название блюда, число порций, позиции с названиями продуктов и граммами.
7. Система фиксирует транзакцию, показывает сообщение об успехе и обновлённые остатки.
8. Сотрудник закрывает сообщение; панель возвращается в состояние «Расход рассчитан».

**Альтернативные потоки.**
- 2a. Число порций вне 1…999 или не число: ошибка у поля, кнопка «Списать» недоступна, пока ввод не исправлен.
- 5a. Не хватает хотя бы одного продукта: транзакция откатывается, остатки и журнал не меняются; выполняется UC-11.
- 4a. Блюдо удалено после показа расхода: откат, сообщение «Блюдо не найдено».
- 6a. Исключение при записи: откат, ошибка записана в лог, показано сообщение; остатки прежние.

**Постусловия.** Успех: остатки уменьшены, добавлена запись журнала. Нехватка или ошибка: остатки и журнал без изменений (BR-9).

### UC-7. Просмотреть журнал списаний

**Описание.** Сотрудник просматривает выполненные списания и ищет их по названию блюда.
**Актёр.** Сотрудник кафе.
**Предусловия.** Приложение запущено.

**Основной поток.**
1. Сотрудник открывает вкладку «Журнал списаний».
2. Система показывает записи, новые сверху: дата и время в локальном часовом поясе, блюдо, число порций, расход по продуктам в граммах.
3. Сотрудник вводит часть названия блюда в поле поиска.
4. Система оставляет записи, в названии блюда которых есть введённый текст без учёта регистра.

**Альтернативные потоки.**
- 2a. Журнал пуст: показан пустой список.
- 4a. Совпадений нет: список пуст.

**Постусловия.** Данные не изменены. Записи остаются видимыми, даже если блюдо или продукт позже удалены (BR-11).

### UC-8. Создать резервную копию и восстановить данные

**Описание.** Сотрудник сохраняет копию БД и изображений в выбранную папку или восстанавливает данные из такой копии.
**Актёр.** Сотрудник кафе.
**Предусловия.** Приложение запущено. Для восстановления существует папка резервной копии.

**Основной поток («Создать копию»).**
1. Сотрудник открывает окно резервного копирования и выбирает «Создать копию».
2. Сотрудник выбирает целевую папку в системном диалоге.
3. Система создаёт папку `backup-yyyyMMdd-HHmmss`, записывает в неё согласованный снимок `cafecalc.db` и копирует `images/`.
4. Система сообщает об успешном создании копии.

**Альтернативные потоки.**
- A. «Восстановить». Сотрудник выбирает папку копии. Система проверяет наличие `cafecalc.db` и `images`, целостность БД и версию схемы (не выше версии приложения), автоматически создаёт копию текущих данных, закрывает соединения, заменяет БД и `images`, перезапускает приложение.
- A1. Проверка не пройдена: сообщение, текущие данные не изменены.
- 2a. Сотрудник отменил выбор папки или нет доступа к ней: сообщение или возврат в окно, данные не изменены.

**Постусловия.** Копия создана и самодостаточна; текущие данные не изменены. После восстановления приложение работает с данными из копии, а прежние данные сохранены в автоматической копии.

### UC-9. Проверить вводимые данные (включаемый)

**Описание.** Общая проверка полей продукта и блюда перед сохранением.
**Актёр.** Нет; вызывается из UC-2, UC-3, UC-5.
**Предусловия.** Сотрудник нажал «Сохранить» или подтвердил ввод.

**Основной поток.**
1. Система нормализует название и формирует ключ названия.
2. Система проверяет длину названия 1…100 символов.
3. Система разбирает граммы: только цифры, значение в допустимом диапазоне (BR-2, BR-3, BR-6).
4. Для блюда система проверяет рецепт 1…5000 символов, наличие хотя бы одного продукта в составе и отсутствие повторов (BR-5, BR-7).
5. Система возвращает вызвавшему прецеденту «корректно».

**Альтернативные потоки.**
- 2a, 3a, 4a. Нарушено правило: система возвращает перечень «поле — сообщение об ошибке»; вызвавший прецедент показывает ошибки рядом с полями.

**Постусловия.** Данные не изменены. Уникальность ключа проверяется позже, внутри транзакции сохранения.

### UC-10. Импортировать изображение (расширение)

**Описание.** Проверка выбранного файла и копирование его в папку изображений приложения.
**Актёр.** Нет; расширяет UC-2, UC-3, UC-5.
**Условие расширения.** Сотрудник выбрал файл изображения в форме (точка расширения «Выбор изображения»).
**Предусловия.** Файл указан; папка `images/` доступна для записи.

**Основной поток.**
1. Система проверяет расширение: `.jpg`, `.jpeg`, `.png` без учёта регистра.
2. Система проверяет, что размер файла не больше 5 МБ.
3. Система проверяет, что файл декодируется как JPEG или PNG.
4. Система копирует файл в `images/<guid>.<ext>` и возвращает относительный путь.

**Альтернативные потоки.**
- 1a, 2a, 3a. Проверка не пройдена: сообщение об ошибке на русском, файл не копируется.

**Постусловия.** Успех: в `images/` есть копия файла. Ошибка: файловая система не изменена.

### UC-11. Показать нехватку продуктов (расширение)

**Описание.** Сообщение о продуктах, которых недостаточно для запрошенного списания.
**Актёр.** Нет; расширяет UC-6.
**Условие расширения.** Остаток хотя бы одного продукта меньше требуемого (точка расширения «Проверка остатков»).
**Предусловия.** Транзакция списания откатена.

**Основной поток.**
1. Система открывает модальное окно со списком: продукт, требуется, остаток, не хватает (в граммах).
2. Сотрудник закрывает окно.

**Постусловия.** Остатки и журнал не изменены; панель списания в состоянии «Расход рассчитан».
