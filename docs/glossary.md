# Глоссарий проекта CafeCalc

Версия 0.1 · 18.11.2026 · Пастухов М. В., гр. 450501

Глоссарий фиксирует единое значение терминов предметной области и проектной документации. Определения согласованы с SDD (`sdd/sdd.md`); при расхождении с SRS 1.3 приоритет у SRS, а глоссарий подлежит исправлению.

| Термин | Определение | Синонимы / не путать с | Где используется |
|--------|-------------|------------------------|------------------|
| Актёр (Actor) | Роль внешнего по отношению к системе лица, другой системы или времени, которая взаимодействует с системой и инициирует прецеденты | Не путать с конкретным человеком: один человек может играть несколько ролей | `use-cases.md` |
| Актёр вспомогательный | Актёр, который участвует в выполнении прецедента, но не инициирует его; в CafeCalc — «База данных» | Вторичный актёр | `use-cases.md` |
| Блюдо | Готовая позиция меню: название, текстовый рецепт, необязательное изображение и состав. Хранится в таблице `Dishes` | Рецепт — лишь часть блюда | UC-4, UC-5, UC-6 |
| Вариант использования (прецедент, Use Case) | Последовательность действий системы в ответ на событие, инициированное актёром, приводящая к наблюдаемому им результату | UC | `use-cases.md` |
| Грамм (г) | Единственная единица измерения количества продукта в версии 1.0; значения — целые числа | Другие единицы отложены до версии 2.0 | REQ-FUNC-009 |
| Диаграмма активности (деятельности) | UML-диаграмма поведения, показывающая последовательность действий, ветвления и циклы сценария | Аналог блок-схемы по ГОСТ 19.701-90 | SDD 007 |
| Диаграмма последовательности | UML-диаграмма взаимодействия, показывающая обмен сообщениями между объектами во времени | — | SDD 006 |
| Диаграмма состояний | UML-диаграмма, показывающая состояния объекта и переходы между ними под действием событий | State machine diagram | SDD 008 |
| Журнал событий приложения | Файл в папке `logs/` с записями о запуске, ошибках и списаниях без персональных данных; хранится не более 30 дней | Не путать с журналом списаний | REQ-OBS-001 |
| Журнал списаний | Хронологический список выполненных списаний; новые записи сверху. Хранит снимки названий | Не путать с журналом событий приложения | UC-7, REQ-FUNC-016 |
| Заглушка изображения | Изображение по умолчанию, показываемое, если у продукта или блюда нет картинки либо файл повреждён или удалён | Null Object | REQ-FUNC-006, REQ-REL-003 |
| Изображение | Файл JPG или PNG размером до 5 МБ, скопированный в папку `images/` под именем `<guid>.<ext>`; в БД хранится относительный путь | — | UC-10, REQ-INT-005 |
| Инкремент | Этап поставки: 1 — Склад, 2 — Меню и рецепты, 3 — Списание и журнал | — | SRS 2.6 |
| Карточка блюда | Область интерфейса с изображением, названием, составом и рецептом выбранного блюда | — | UC-4, REQ-FUNC-012 |
| Ключ названия (NameKey) | Нормализованное название: без пробелов по краям, с единичными пробелами внутри, в верхнем регистре. Служит для проверки уникальности и хранится с уникальным индексом | — | REQ-FUNC-005 |
| Меню блюд | Вкладка и совокупность всех блюд кафе | — | UC-4, UC-5 |
| Миграция | Версионируемый скрипт изменения схемы БД (EF Core), применяемый при запуске | — | ADR-0004 |
| Нехватка | Ситуация, когда остаток хотя бы одного продукта меньше требуемого для списания; описывается позицией: продукт, требуется, остаток, не хватает | Дефицит | UC-11, REQ-FUNC-015 |
| Низкий остаток | Остаток продукта меньше 300 г; в списке выделяется красным. Порог задан константой | Не путать с нехваткой | REQ-FUNC-001 |
| Остаток | Текущее количество продукта на складе в граммах, целое число от 0 до 10 000 000 | StockGrams | REQ-FUNC-005 |
| Папка данных | Каталог `%LOCALAPPDATA%\CafeCalc\` (или заданный `CAFECALC_DATA_DIR`) с БД, изображениями и журналами | — | SDD 010 |
| Пополнение | Увеличение остатка продукта на введённое число граммов (не менее 1) | — | UC-3, REQ-FUNC-007 |
| Порция | Единица выпуска блюда; состав блюда задаётся на 1 порцию, число порций при списании — от 1 до 999 | — | UC-6 |
| Постусловие | Состояние системы, которое гарантированно достигается после завершения прецедента | Post-condition | `use-cases.md` |
| Поток событий | Пошаговое описание прецедента: основной (нормальный) и альтернативные потоки, потоки ошибок | Flow of Events | `use-cases.md` |
| Предусловие | Условие, которое должно выполняться до начала прецедента | Pre-condition | `use-cases.md` |
| Предпросмотр расхода | Расчёт «продукт — граммы к списанию» (`WriteOffPlan`), показываемый до нажатия «Списать» | — | UC-6, SDD 007 (A4) |
| Продукт | Складская позиция: название, остаток в граммах, необязательное изображение. Хранится в таблице `Products` | Ингредиент — продукт в составе блюда | UC-1…UC-3 |
| Резервная копия | Папка `backup-yyyyMMdd-HHmmss` с согласованным снимком `cafecalc.db` и копией `images/` | Бэкап | UC-8, REQ-REL-002 |
| Рецепт | Текстовое описание приготовления блюда длиной 1…5000 символов; переносы строк сохраняются | — | REQ-FUNC-013 |
| Склад | Вкладка и совокупность всех продуктов с остатками | — | UC-1…UC-3 |
| Списание | Одна атомарная операция: уменьшение остатков продуктов состава блюда на «граммы × порции» и запись в журнал | — | UC-6 |
| Снимок (snapshot) | Копия данных на момент операции: журнал хранит названия блюда и продуктов, а не ссылки на них | — | REQ-FUNC-016 |
| Состав блюда | Набор пар «продукт — граммы на порцию»; не менее одного продукта, без повторов | Ингредиенты блюда | REQ-FUNC-011 |
| Сотрудник кафе | Единственный актёр системы: повар, кладовщик или администратор, работающий с приложением на одном ПК | Пользователь | SRS 2.4 |
| Транзакция / единица работы (UoW) | Группа операций с БД, выполняемая по принципу «всё или ничего» | Unit of Work | REQ-REL-001 |
