# Дополнительные спецификации CafeCalc

Версия 0.1 · 18.11.2026 · Пастухов М. В., гр. 450501

Документ собирает требования, не выражаемые прецедентами: нефункциональные характеристики, ограничения и бизнес-правила. Источники — SRS (идентификаторы `REQ-*`) и SDD (`sdd/sdd.md`, представления 004, 007, 011, 012). Числовые значения взяты из SDD; при расхождении с SRS приоритет у SRS. Термины — в `glossary.md`.

## 1. Удобство использования

| ID | Требование | Мера | Источник |
|----|-----------|------|----------|
| SS-US-1 | Главное окно с вкладками «Склад», «Меню блюд», «Журнал списаний»; создание и правка — в модальных окнах | Модальные окна блокируют главное окно | REQ-INT-001 |
| SS-US-2 | Интерфейс на русском языке, культура `ru-RU`, единицы только «г» | Проверка осмотром | REQ-INT-002 |
| SS-US-3 | Минимальный размер окна 1280×720, приложение DPI-aware (PerMonitorV2) | `MinWidth`/`MinHeight` | REQ-INT-002, DR-9 |
| SS-US-4 | Ошибки ввода показываются рядом с полем красным текстом; окно остаётся открытым | `INotifyDataErrorInfo` | REQ-INT-002 |
| SS-US-5 | Горячие клавиши: `Ctrl+F` — фокус на поиск, `Esc` — закрыть модальное окно, `Enter` — подтвердить форму | — | REQ-INT-003 |
| SS-US-6 | Кнопки, неприменимые в текущем состоянии, недоступны; на время операции все кнопки блокируются | Диаграмма состояний 004 | REQ-FUNC-003, 014 |

## 3. Надёжность и целостность данных

| ID | Требование | Мера | Источник |
|----|-----------|------|----------|
| SS-RL-1 | Операции над несколькими записями (списание, сохранение блюда) атомарны | Одна транзакция, откат при любой ошибке | REQ-REL-001 |
| SS-RL-2 | Остаток не может стать отрицательным | Проверка в сервисе и `CHECK (StockGrams >= 0)` | REQ-SEC-001 |
| SS-RL-3 | Целостность обеспечивается на трёх уровнях: UI, сервис, ограничения БД | Defense in depth | REQ-SEC-001 |
| SS-RL-4 | Необработанные ошибки не завершают приложение: запись в лог, сообщение на русском | Глобальные обработчики | REQ-REL-003 |
| SS-RL-5 | Резервное копирование и восстановление данных | `VACUUM INTO`, `integrity_check` | REQ-REL-002 |
| SS-RL-6 | Отсутствие или повреждение файла изображения не нарушает работу интерфейса | Заглушка | REQ-REL-003 |
| SS-RL-7 | Автономная работа без сети; один экземпляр приложения (именованный Mutex) | — | REQ-AVAIL-001, DR-4 |

## 4. Безопасность и конфиденциальность

| ID | Требование | Источник |
|----|-----------|----------|
| SS-SC-1 | Сетевые соединения не используются; данные не покидают ПК | REQ-SEC-002 |
| SS-SC-2 | Авторизация и роли в версии 1.0 не реализуются (отложено до 2.0); все пользователи эквивалентны актёру «Сотрудник кафе» | SDD 5.1 |
| SS-SC-3 | Журнал событий не содержит персональных данных | REQ-OBS-001 |

## 5. Поддерживаемость

| ID | Требование | Мера | Источник |
|----|-----------|------|----------|
| SS-SP-1 | Три слоя App → Core ← Infrastructure; бизнес-логика Core не зависит от WPF и EF | Модульные тесты Core без UI и БД | REQ-MAINT-001, ADR-0003 |
| SS-SP-2 | Журнал событий: запуск, ошибки, списания; хранение не более 30 дней | Serilog, File sink | REQ-OBS-001, ADR-0008 |
| SS-SP-3 | Воспроизводимая сборка командой `dotnet build` без ручной настройки | `global.json`, `Directory.Packages.props` | REQ-BUILD-001 |
| SS-SP-4 | Диаграммы и документация хранятся в репозитории как текст (PlantUML, Markdown) | ADR-0009 | — |

## 6. Ограничения проектирования и реализации

| ID | Ограничение | Источник |
|----|-------------|----------|
| SS-CN-1 | Платформа: Windows 10/11 x64, проверка на обеих ОС | REQ-PORT-001 |
| SS-CN-2 | Технологии: C#, WPF + MVVM, .NET 10 LTS (self-contained), SQLite + EF Core | ADR-0001, 0002, 0004 |
| SS-CN-3 | Установка копированием папки: не более 5 шагов, без прав администратора, без установки СУБД и runtime | REQ-INST-001 |
| SS-CN-4 | Данные в `%LOCALAPPDATA%\CafeCalc\`, изображения — файлами с относительными путями | ADR-0007 |
| SS-CN-5 | Все библиотеки бесплатны; лицензии перечислены в `docs/licenses.md` | REQ-COST-001, REQ-COMP-001 |

## 7. Бизнес-правила

| ID | Правило | Где применяется |
|----|---------|-----------------|
| BR-1 | Название продукта и блюда: 1…100 символов; уникально без учёта регистра и лишних пробелов (по ключу названия) | UC-2, UC-3, UC-5, UC-9 |
| BR-2 | Количество граммов вводится только цифрами 0–9: без знаков, запятых, пробелов и единиц | UC-3, UC-5, UC-9 |
| BR-3 | Остаток продукта — целое от 0 до 10 000 000 г; пополнение — не менее 1 г | UC-2, UC-3 |
| BR-4 | Число порций при списании — целое от 1 до 999 | UC-6 |
| BR-5 | Блюдо содержит не менее одного продукта; продукт в составе не повторяется | UC-5, UC-9 |
| BR-6 | Граммы продукта на порцию: от 1 до 100 000 (значение предложено в DR-3, требует согласования с заказчиком) | UC-5, UC-9 |
| BR-7 | Рецепт: 1…5000 символов | UC-5, UC-9 |
| BR-8 | Продукт, входящий в состав блюда, удалить нельзя; показывается перечень блюд | UC-3 |
| BR-9 | Списание выполняется целиком или не выполняется; при нехватке хотя бы одного продукта остатки не меняются | UC-6, UC-11 |
| BR-10 | Расход продукта = граммы на порцию × число порций | UC-6 |
| BR-11 | Журнал хранит названия на момент списания; записи переживают удаление блюда и продукта | UC-6, UC-7 |
| BR-12 | Изображение: JPG/JPEG/PNG, не более 5 МБ, должно декодироваться | UC-10 |
| BR-13 | Остаток меньше 300 г выделяется красным в списке продуктов | UC-1 |
| BR-14 | Время хранится в UTC, отображается в локальном времени | UC-7 |
