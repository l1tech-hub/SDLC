# Данные хранятся в %LOCALAPPDATA%\CafeCalc, изображения — файлами с относительными путями, резервная копия — через VACUUM INTO

## Контекст и постановка задачи

SRS требует: при выборе изображения копировать файл в папку данных приложения и хранить относительный путь, чтобы изображение отображалось и после удаления исходного файла (REQ-INT-005); поддерживать JPG и PNG до 5 МБ; устанавливать приложение копированием папки без прав администратора, не затрагивать пользовательские данные при удалении приложения (REQ-INST-001); предоставлять резервное копирование БД и изображений и восстановление (REQ-REL-002); вести файл журнала в папке данных (REQ-OBS-001). Папка с программой (например, `Program Files`) может быть недоступна для записи.

Где хранить БД, изображения и журналы, как хранить изображения и как делать согласованную резервную копию работающей БД?

## Драйверы решения

* Запись без прав администратора (REQ-INST-001).
* Сохранность данных при удалении и переустановке приложения (REQ-INST-001).
* Независимость изображений от исходных файлов (REQ-INT-005).
* Согласованная резервная копия при открытой БД (REQ-REL-002).
* Доступ к данным ограничивается средствами учётной записи Windows (REQ-SEC-002).
* Устойчивость к потере или порче файла изображения (REQ-REL-003).

## Рассмотренные варианты

Расположение данных:

* Рядом с исполняемым файлом
* `%LOCALAPPDATA%\CafeCalc`
* `%APPDATA%\CafeCalc` (роуминг)
* `%ProgramData%\CafeCalc`

Хранение изображений:

* Файлы в папке данных, относительный путь в БД
* BLOB в БД
* Абсолютный путь к исходному файлу

Резервная копия:

* `VACUUM INTO` + копирование папки изображений
* Копирование файла БД «как есть»

## Итог решения

Выбранные варианты:

* Расположение: «`%LOCALAPPDATA%\CafeCalc`» (подпапки `images/`, `logs/`, файл `cafecalc.db`), потому что запись туда разрешена обычному пользователю, данные отделены от программы и переживают её удаление; расположение можно переопределить переменной окружения `CAFECALC_DATA_DIR` (удобно для тестов).
* Изображения: «файлы в папке данных, относительный путь в БД», потому что это прямо требует REQ-INT-005. Файл получает имя `<guid>.<ext>` (нет коллизий и небезопасных имён). Перед копированием проверяются расширение, размер ≤ 5 МБ и реальная декодируемость как JPEG/PNG. Старый файл удаляется после успешной фиксации изменений; «осиротевшие» файлы удаляются при запуске. Потеря файла — не ошибка: показывается заглушка.
* Резервная копия: «`VACUUM INTO` + копирование папки изображений» в подпапку `backup-yyyyMMdd-HHmmss`, потому что `VACUUM INTO` создаёт согласованный снимок открытой БД. Восстановление: проверка копии (открытие БД, `PRAGMA integrity_check`, версия схемы не новее приложения), автоматическая копия текущих данных, замена данных и перезапуск.

### Последствия

* Хорошо, потому что приложение работает без прав администратора и без записи в папку программы.
* Хорошо, потому что удаление приложения не уничтожает данные.
* Хорошо, потому что копия БД согласована даже при работающем приложении.
* Плохо, потому что данные привязаны к учётной записи Windows: другой пользователь на том же ПК их не увидит (для одного рабочего места допустимо, A-1; для переноса используется резервная копия).
* Плохо, потому что файлы изображений и записи БД могут расходиться (удалённый вручную файл) — смягчается заглушкой и очисткой при запуске.
* Нейтрально: размер резервной копии зависит от объёма изображений.

### Подтверждение

* Тесты `ImageStore`: допустимые JPG и PNG копируются; файл другого формата, > 5 МБ и «переименованный» не-изображение отклоняются с сообщением; после удаления исходного файла изображение отображается (REQ-INT-005).
* Тест устойчивости: удаление файла из `images/` не вызывает падения, показывается заглушка (REQ-REL-003).
* Интеграционный тест резервной копии: создание копии, изменение данных, восстановление — состояние совпадает с моментом копирования (REQ-REL-002).
* Демонстрация REQ-INST-001: запуск без прав администратора, повторная установка сохраняет данные.

## Плюсы и минусы вариантов

### Рядом с исполняемым файлом

* Хорошо, потому что переносимая установка («всё в одной папке»).
* Плохо, потому что при установке в `Program Files` запись недоступна без прав администратора.
* Плохо, потому что удаление папки приложения стирает данные.

### %LOCALAPPDATA%\CafeCalc

* Хорошо, потому что стандартное место для данных пользователя без прав администратора.
* Хорошо, потому что данные отделены от программы.
* Плохо, потому что данные привязаны к учётной записи Windows.

### %APPDATA%\CafeCalc (роуминг)

* Хорошо, потому что данные могут следовать за пользователем в доменной среде.
* Плохо, потому что роуминг крупных файлов (БД, изображений) нежелателен и избыточен для одного ПК.

### %ProgramData%\CafeCalc

* Хорошо, потому что общая папка для всех пользователей ПК.
* Плохо, потому что права записи по умолчанию ограничены; файлы, созданные одним пользователем, не всегда доступны другим, нужна настройка прав.

### Файлы в папке данных, относительный путь в БД

* Хорошо, потому что соответствует REQ-INT-005 и не зависит от исходных файлов.
* Плохо, потому что нужно синхронизировать файлы и записи БД (очистка при удалении и запуске).

### BLOB в БД

* Хорошо, потому что всё в одном файле, проще резервная копия.
* Плохо, потому что разрастание файла БД и замедление операций, неудобно кэшировать миниатюры; противоречит формулировке REQ-INT-005.

### Абсолютный путь к исходному файлу

* Хорошо, потому что проще всего.
* Плохо, потому что нарушает REQ-INT-005: после удаления или перемещения файла изображение пропадает.

### VACUUM INTO + копирование папки изображений

* Хорошо, потому что согласованный снимок открытой БД и простое восстановление.
* Нейтрально, потому что копируются все файлы изображений.

### Копирование файла БД «как есть»

* Хорошо, потому что минимум кода.
* Плохо, потому что при открытой БД копия может быть неконсистентной или заблокированной.

## Дополнительная информация

Связанные требования SRS: REQ-INT-005, REQ-FUNC-006, REQ-INST-001, REQ-REL-002, REQ-REL-003, REQ-OBS-001, REQ-SEC-002, допущение A-1. Связанные представления SDD: 007-algorithm (A6, A7), 010-deployment, 011-resources. Связанные ADR: ADR-0004, ADR-0008. В SRS под «папкой данных приложения» теперь понимается `%LOCALAPPDATA%\CafeCalc\` (SDD 5.3, DR-8).

Пересмотреть решение, если появятся несколько пользователей Windows на одном ПК, которым нужна общая база, либо потребуется работа нескольких рабочих мест.
