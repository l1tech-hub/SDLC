# Платформа .NET 10 LTS и самодостаточная поставка win-x64 вместо .NET 8 с установленным runtime

## Контекст и постановка задачи

Допущение D-1 в SRS предполагает зависимость от .NET 8 Runtime. На дату проектирования (11.11.2026) поддержка .NET 8 завершилась: по политике Microsoft .NET 8 (LTS) и .NET 9 (STS) закончили поддержку 10.11.2026, актуальная LTS-версия — .NET 10, поддерживаемая до ноября 2028. Приложения на .NET 8 продолжают запускаться, но не получают исправлений безопасности.

Одновременно REQ-INST-001 требует установки на «чистую» Windows копированием папки или установщиком без прав разработчика и без отдельной установки СУБД, не более чем за 5 шагов; REQ-BUILD-001 — сборку одной командой.

Какую версию .NET выбрать и как поставлять приложение, чтобы оно было поддерживаемым и простым в установке?

## Драйверы решения

* Поддерживаемость: выпуск версии 1.0 после окончания поддержки .NET 8 нежелателен.
* Простая установка в кафе без ИТ-подготовки (REQ-INST-001, SRS 2.4).
* Работа без сети и без прав администратора (REQ-AVAIL-001, REQ-SEC-002).
* Воспроизводимая сборка (REQ-BUILD-001) и бесплатность (REQ-COST-001).
* Платформа: Windows 10/11 x64 (REQ-PORT-001).
* Размер поставки — второстепенный фактор.

## Рассмотренные варианты

* .NET 8, framework-dependent (как в D-1)
* .NET 10, framework-dependent
* .NET 10, self-contained (win-x64)
* .NET Framework 4.8

## Итог решения

Выбранный вариант: «.NET 10, self-contained (win-x64)», потому что это единственный вариант, одновременно поддерживаемый производителем (до ноября 2028) и не требующий установки runtime на компьютер кафе. Trimming не используется (WPF его не поддерживает), одиночный файл не требуется — поставляется папка.

### Последствия

* Хорошо, потому что версия 1.0 выходит на поддерживаемой платформе, а установка сводится к копированию папки (REQ-INST-001).
* Хорошо, потому что поведение не зависит от версий .NET, оказавшихся на ПК кафе.
* Плохо, потому что размер поставки заметно больше, чем у framework-dependent (приемлемо для локальной установки).
* Плохо, потому что обновления безопасности runtime доставляются только выпуском новой сборки.
* Плохо, потому что требуется правка SRS D-1 (DR-1 в SDD 5.3), а также Rider и .NET SDK должны поддерживать `net10.0`.
* Риск: нужно подтвердить поддержку конкретных сборок Windows 10 на целевых ПК по таблице поддерживаемых ОС .NET 10.

### Подтверждение

* `global.json` фиксирует версию SDK; `TargetFramework = net10.0-windows` (App) и `net10.0` (Core, Infrastructure).
* Демонстрация REQ-INST-001: запуск опубликованной папки на «чистой» Windows 10 и Windows 11 без предустановленного .NET.
* Демонстрация REQ-BUILD-001: `dotnet build` и `dotnet publish -c Release -r win-x64 --self-contained true` на чистой машине.

## Плюсы и минусы вариантов

### .NET 8, framework-dependent

* Хорошо, потому что соответствует SRS D-1 без правок.
* Плохо, потому что поддержка закончилась 10.11.2026.
* Плохо, потому что на ПК кафе нужно устанавливать runtime (нарушает дух REQ-INST-001).

### .NET 10, framework-dependent

* Хорошо, потому что малый размер поставки и поддерживаемая платформа.
* Плохо, потому что нужно установить .NET 10 Desktop Runtime на каждый ПК кафе, в том числе без интернета.

### .NET 10, self-contained (win-x64)

* Хорошо, потому что поддерживается до ноября 2028 и не требует предустановки.
* Хорошо, потому что установка копированием папки (REQ-INST-001).
* Плохо, потому что больше размер и обновление runtime только пересборкой.

### .NET Framework 4.8

* Хорошо, потому что предустановлен на большинстве Windows 10/11.
* Плохо, потому что устаревший стек без современных возможностей .NET, хуже подходит для новых разработок, а наличие в Rider и в учебном курсе современного .NET делает его нецелесообразным.

## Дополнительная информация

Источник сведений о сроках поддержки: .NET and .NET Core Support Policy (Microsoft), см. SDD 1.4, ссылка 9. Связанные требования SRS: REQ-INST-001, REQ-BUILD-001, REQ-PORT-001, REQ-AVAIL-001, допущение D-1. Связанные представления SDD: 010-deployment, 014-dependency.

Пересмотреть решение, если: Заказчик потребует Linux/macOS (смена платформы), либо приблизится окончание поддержки .NET 10 (ноябрь 2028) — тогда запланировать переход на следующую LTS.
