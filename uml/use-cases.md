# Модель вариантов использования CafeCalc

Документ описывает актёров и варианты использования (прецеденты) приложения CafeCalc. Он выведен из SRS и SDD. Термины определены в [глоссарии](glossary.md), бизнес-правила и нефункциональные требования — в [дополнительных спецификациях](supplementary-spec.md).

Потоки прецедентов — первичный источник для диаграмм деятельности, последовательности и состояний (см. [ADR 0009](adr/0009-uml-dynamic-modeling-plantuml.md)). Если имя или шаг в этом документе меняется, нужно проверить связанные диаграммы (раздел «Трассировка к диаграммам»).

## Диаграмма вариантов использования

![Диаграмма вариантов использования](uml/001-usecase-model.svg)

Исходный код диаграммы: [uml/001-usecase-model.puml](uml/001-usecase-model.puml).

Правила построения:

- актёры находятся вне границы системы, связи между актёрами не моделируются;
- каждый основной прецедент инициирован актёром «Сотрудник кафе» (сплошная стрелка от актёра к прецеденту);
- для внешнего исполнителя, который только принимает запросы системы («База данных»), стрелка идёт от прецедента к актёру;
- основные прецеденты не соединяются между собой коммуникационной связью; используются только `include` (общее повторяющееся поведение, стрелка от базового прецедента к включаемому) и `extend` (необязательное или условное расширение, стрелка от расширяющего прецедента к базовому);
- у каждого `extend` указано условие расширения.

## Актёры

| Актёр | Тип | Описание |
|-------|-----|----------|
| Сотрудник кафе | Основной | Повар, кладовщик или администратор. Разделения прав нет: любой сотрудник может выполнять любой прецедент. Единственный человек, который работает с приложением. |
| База данных | Вторичный (внешний исполнитель) | Локальное хранилище SQLite, доступное через EF Core. Принимает запросы на чтение и запись и подтверждает или откатывает транзакции. Сети и других внешних систем у приложения нет. |

## Описание прецедентов

### UC-1 Просмотреть склад, найти и выбрать продукт

- **Актёры**: Сотрудник кафе; База данных (чтение).
- **Пояснение**: сотрудник просматривает список продуктов с остатками, ищет нужный по названию и выбирает его для дальнейших действий.
- **Предусловия**: приложение запущено.
- **Основной поток**:
  1. Сотрудник открывает вкладку «Склад».
  2. Система читает продукты и показывает список: название, остаток в граммах, изображение (если есть).
  3. Система выделяет красным продукты с остатком < 300 г.
  4. Сотрудник вводит часть названия в строку поиска.
  5. Система показывает продукты, подходящие под запрос.
  6. Сотрудник выбирает продукт в списке.
  7. Система показывает выбранный продукт и делает доступными действия UC-3.
- **Альтернативные потоки**:
  - A1: поле поиска пусто — показан весь список.
  - A2: продуктов нет — система показывает пустой список и предлагает добавить продукт (UC-2).
  - A3: по запросу ничего не найдено — система показывает сообщение «Ничего не найдено».
- **Потоки ошибок**:
  - E1: не удалось прочитать базу данных — система показывает сообщение об ошибке, список не обновляется.
- **Постусловия**: на экране актуальный список продуктов; данные не изменены.

### UC-2 Добавить продукт

- **Актёры**: Сотрудник кафе; База данных (запись).
- **Пояснение**: сотрудник создаёт новый продукт с названием, начальным остатком и, при желании, изображением.
- **Предусловия**: приложение запущено, открыта вкладка «Склад».
- **Основной поток**:
  1. Сотрудник нажимает «Добавить продукт».
  2. Система открывает модальное окно «Новый продукт».
  3. Сотрудник вводит название и остаток и при желании выбирает изображение.
  4. Сотрудник нажимает «Сохранить».
  5. Система проверяет название и остаток (UC-9).
  6. Если выбрано изображение, система проверяет и копирует его (UC-10).
  7. Система в одной транзакции проверяет уникальность ключа названия (NameKey) и добавляет продукт.
  8. Система фиксирует транзакцию, закрывает окно и показывает продукт в списке.
- **Альтернативные потоки**:
  - A1 (отмена): сотрудник нажимает «Отмена»; система закрывает окно без сохранения, данные и файлы не изменены.
  - A2 (исправление): после сообщения об ошибке сотрудник исправляет данные, шаги 3–7 повторяются.
- **Потоки ошибок**:
  - E1: данные не прошли проверку (UC-9) — система показывает ошибки рядом с полями, окно остаётся открытым.
  - E2: изображение не прошло проверку (UC-10) — система показывает сообщение, окно остаётся открытым.
  - E3: ключ названия занят или сбой записи — система откатывает транзакцию, удаляет скопированный файл изображения, показывает сообщение об ошибке, окно остаётся открытым.
- **Постусловия**: продукт сохранён в базе данных, изображение (если было) лежит в `images/`; при ошибке или отмене состояние данных и файлов не изменилось.

### UC-3 Пополнить, изменить, удалить продукт

- **Актёры**: Сотрудник кафе; База данных (чтение и запись).
- **Пояснение**: сотрудник увеличивает остаток выбранного продукта, меняет его данные или удаляет продукт.
- **Предусловия**: в списке выбран продукт (UC-1).
- **Основной поток (пополнение)**:
  1. Сотрудник выбирает «Пополнить» и вводит количество граммов.
  2. Система проверяет количество и итоговый остаток (UC-9).
  3. Система в одной транзакции увеличивает остаток и фиксирует транзакцию.
  4. Система показывает новый остаток в списке.
- **Альтернативные потоки**:
  - A1 (изменение): сотрудник выбирает «Изменить», правит название, остаток или изображение (UC-10); шаги проверки и сохранения такие же, как в UC-2.
  - A2 (удаление): сотрудник выбирает «Удалить» и подтверждает; система удаляет продукт и показывает обновлённый список.
  - A3 (отмена): сотрудник закрывает окно или отказывается от удаления, данные не изменены.
- **Потоки ошибок**:
  - E1: данные не прошли проверку (UC-9), в том числе итоговый остаток больше 10 000 000 г — система показывает сообщение, окно остаётся открытым.
  - E2: ключ названия занят или сбой записи — откат транзакции, сообщение об ошибке.
- **Постусловия**: данные продукта соответствуют выполненному действию; при ошибке состояние не изменилось.

### UC-4 Просмотреть меню, найти блюдо, открыть карточку и рецепт

- **Актёры**: Сотрудник кафе; База данных (чтение).
- **Пояснение**: сотрудник просматривает список блюд, ищет блюдо по названию и открывает его карточку с рецептом и составом.
- **Предусловия**: приложение запущено.
- **Основной поток**:
  1. Сотрудник открывает вкладку «Меню».
  2. Система показывает список блюд.
  3. Сотрудник вводит часть названия в строку поиска.
  4. Система показывает подходящие блюда.
  5. Сотрудник выбирает блюдо.
  6. Система открывает карточку: название, изображение, текст рецепта, состав (продукты и граммы на 1 порцию).
- **Альтернативные потоки**:
  - A1: блюд нет — система показывает пустой список и предлагает создать блюдо (UC-5).
  - A2: по запросу ничего не найдено — сообщение «Ничего не найдено».
- **Потоки ошибок**:
  - E1: не удалось прочитать базу данных — сообщение об ошибке.
- **Постусловия**: на экране карточка выбранного блюда; данные не изменены.

### UC-5 Создать, изменить, удалить блюдо

- **Актёры**: Сотрудник кафе; База данных (запись).
- **Пояснение**: сотрудник создаёт блюдо с рецептом, изображением и составом, изменяет его или удаляет.
- **Предусловия**: открыта вкладка «Меню»; для создания состава в базе есть продукты.
- **Основной поток (создание)**:
  1. Сотрудник нажимает «Добавить блюдо».
  2. Система открывает модальное окно «Новое блюдо».
  3. Сотрудник вводит название и текст рецепта, при желании выбирает изображение.
  4. Сотрудник добавляет в состав продукты и указывает граммы на 1 порцию для каждого.
  5. Сотрудник нажимает «Сохранить».
  6. Система проверяет название, рецепт и состав (UC-9).
  7. Если выбрано изображение, система проверяет и копирует его (UC-10).
  8. Система в одной транзакции проверяет уникальность ключа названия и сохраняет блюдо с составом, затем фиксирует транзакцию.
  9. Система закрывает окно и показывает блюдо в меню.
- **Альтернативные потоки**:
  - A1 (изменение): сотрудник выбирает блюдо и «Изменить», шаги 3–9 выполняются для существующего блюда.
  - A2 (удаление): сотрудник выбирает «Удалить» и подтверждает; система удаляет блюдо.
  - A3 (отмена): сотрудник закрывает окно, изменений нет.
- **Потоки ошибок**:
  - E1: данные не прошли проверку (UC-9): рецепт короче 1 или длиннее 5000 символов, состав пуст, продукт повторяется — сообщение, окно остаётся открытым.
  - E2: изображение не прошло проверку (UC-10) — сообщение, окно остаётся открытым.
  - E3: ключ названия занят или сбой записи — откат транзакции, удаление скопированного файла, сообщение об ошибке.
- **Постусловия**: блюдо сохранено с составом без повторов; при ошибке состояние не изменилось.

### UC-6 Списать продукты по блюду

- **Актёры**: Сотрудник кафе; База данных (чтение и запись).
- **Пояснение**: сотрудник списывает со склада продукты, израсходованные на приготовление выбранного блюда в заданном числе порций.
- **Предусловия**: в меню есть блюдо; приложение запущено.
- **Основной поток**:
  1. Сотрудник открывает панель списания и выбирает блюдо.
  2. Система делает доступным поле числа порций.
  3. Сотрудник вводит число порций (1…999).
  4. Система проверяет число порций (UC-9) и рассчитывает расход по каждому продукту: граммы на 1 порцию × число порций.
  5. Система показывает расход в граммах и делает доступной кнопку «Списать».
  6. Сотрудник нажимает «Списать».
  7. Система блокирует элементы управления и показывает индикатор выполнения.
  8. Система в одной транзакции проверяет остатки, уменьшает их и записывает операцию в журнал со снимками названий.
  9. Система фиксирует транзакцию, показывает сообщение об успехе и обновляет остатки.
- **Альтернативные потоки**:
  - A1: сотрудник снимает выбор блюда — панель возвращается в исходное состояние, кнопка «Списать» недоступна.
  - A2: сотрудник меняет число порций — расход пересчитывается (шаги 4–5).
- **Потоки ошибок**:
  - E1: число порций вне диапазона 1…999 — система показывает ошибку у поля, кнопка «Списать» недоступна.
  - E2: остатков недостаточно — система откатывает транзакцию, остатки не меняются, выполняется расширение UC-11.
  - E3: исключение при выполнении — система откатывает транзакцию, показывает сообщение об ошибке, остатки не меняются.
- **Постусловия**: при успехе остатки уменьшены, запись добавлена в журнал; при нехватке или ошибке остатки и журнал не изменились (операция атомарна).

### UC-7 Просмотреть журнал списаний

- **Актёры**: Сотрудник кафе; База данных (чтение).
- **Пояснение**: сотрудник просматривает историю выполненных списаний.
- **Предусловия**: приложение запущено.
- **Основной поток**:
  1. Сотрудник открывает вкладку «Журнал».
  2. Система читает записи и показывает их списком: блюдо, число порций, списанные продукты в граммах, время операции.
  3. Названия блюд и продуктов показаны такими, какими они были на момент списания (снимки названий).
- **Альтернативные потоки**:
  - A1: записей нет — система показывает сообщение «Списаний ещё не было».
- **Потоки ошибок**:
  - E1: не удалось прочитать базу данных — сообщение об ошибке.
- **Постусловия**: на экране журнал; записи не изменяются и не удаляются из этого прецедента.

### UC-8 Создать резервную копию и восстановить данные

- **Актёры**: Сотрудник кафе; База данных (чтение и запись).
- **Пояснение**: сотрудник сохраняет копию данных приложения и при необходимости восстанавливает данные из неё.
- **Предусловия**: приложение запущено.
- **Основной поток (создание копии)**:
  1. Сотрудник выбирает «Создать резервную копию».
  2. Сотрудник выбирает место сохранения.
  3. Система сохраняет копию данных (база данных и изображения).
  4. Система сообщает об успешном создании копии.
- **Альтернативные потоки**:
  - A1 (восстановление): сотрудник выбирает «Восстановить», указывает файл копии и подтверждает замену текущих данных; система восстанавливает данные и обновляет экраны.
  - A2 (отмена): сотрудник отказывается от выбора файла или подтверждения, данные не изменены.
- **Потоки ошибок**:
  - E1: нет прав на запись или место недоступно — сообщение об ошибке, копия не создана.
  - E2: файл копии повреждён или не подходит — сообщение, текущие данные не изменяются.
- **Постусловия**: копия создана или данные восстановлены из копии; при ошибке текущие данные остались прежними.

### UC-9 Проверить вводимые данные

- **Актёры**: нет (включается в UC-2, UC-3, UC-5; в UC-6 применяется к полю числа порций).
- **Пояснение**: общее поведение проверки значений, которые вводит сотрудник.
- **Предусловия**: вызывающий прецедент передал значение и его тип.
- **Основной поток**:
  1. Система проверяет формат значения (число, текст, непустое поле).
  2. Система проверяет допустимый диапазон:
     - остаток продукта: целое 0…10 000 000 г;
     - рецепт: 1…5000 символов;
     - состав блюда: не меньше одного продукта, без повторов;
     - число порций: целое 1…999.
  3. Система возвращает вызывающему прецеденту признак успеха.
- **Альтернативные потоки**: нет.
- **Потоки ошибок**:
  - E1: значение недопустимо — система возвращает сообщение с указанием допустимого формата или диапазона.
- **Постусловия**: вызывающий прецедент получил результат проверки.

### UC-10 Импортировать изображение

- **Актёры**: нет (расширяет UC-2, UC-3, UC-5).
- **Условие расширения**: сотрудник выбрал файл изображения.
- **Пояснение**: система проверяет выбранный файл и копирует его в папку `images/` приложения.
- **Предусловия**: в диалоге продукта или блюда выбран файл изображения.
- **Основной поток**:
  1. Система проверяет формат файла: JPG или PNG.
  2. Система проверяет размер файла: не более 5 МБ.
  3. Система копирует файл в `images/` под новым именем.
  4. Система возвращает вызывающему прецеденту относительный путь к файлу.
- **Альтернативные потоки**:
  - A1: изображение не выбрано — расширение не выполняется, продукт или блюдо сохраняется без изображения.
  - A2: при замене изображения старый файл удаляется после успешного сохранения.
- **Потоки ошибок**:
  - E1: формат не JPG и не PNG, либо размер больше 5 МБ — система возвращает сообщение, файл не копируется.
  - E2: не удалось прочитать или скопировать файл — сообщение об ошибке.
- **Постусловия**: файл лежит в `images/`, путь передан вызывающему прецеденту; при ошибке копия не создаётся.

### UC-11 Показать нехватку продуктов

- **Актёры**: нет (расширяет UC-6).
- **Условие расширения**: остатков недостаточно для списания.
- **Пояснение**: система объясняет сотруднику, каких продуктов не хватает для выбранного блюда и числа порций.
- **Предусловия**: при выполнении UC-6 обнаружено, что расход превышает остаток хотя бы по одному продукту.
- **Основной поток**:
  1. Система формирует список продуктов с нехваткой.
  2. Система показывает окно нехватки: название продукта, требуется, на складе, не хватает (в граммах).
  3. Сотрудник закрывает окно.
  4. Система возвращает панель списания в состояние с рассчитанным расходом.
- **Альтернативные потоки**: нет.
- **Потоки ошибок**: отсутствуют.
- **Постусловия**: остатки и журнал не изменены; сотрудник может изменить число порций или выбрать другое блюдо.
